Every repository grows its own habits. Some of them are good, and most of them live only in someone's head.

## What goes in the file

- how a change is proposed and reviewed
- what a finished pull request looks like
- which checks must pass, and why

> A rule nobody can find is a rule nobody follows.

Once it is written down, a person or an agent can apply it the same way every time. The tool that does this for my repositories is [Repo Standards](https://repo-standards.com/):

```
npx @lutzseverino/repo-standards adopt <source>
```

## What stays out

Taste. A file can say *what* a good change contains. It cannot make anyone care about the reader, and it should not pretend to.
